# 0008. Mode A の外側の基底ケース:忠実なスキャン版 Dijkstra と、逸脱 D-1 としての二分ヒープ版

[English](0008-mode-a-outer-base-case-variants.md) | **日本語** | [简体中文](0008-mode-a-outer-base-case-variants.zh-CN.md)

- 状態: Accepted
- 日付: 2026-11-27

## 背景 (Context)
Algorithm 8 (Sec 8.3、疑似コードの 4〜7 行目)は、`N <= L_N^64` のとき、直接の探索を返します。外側の条件 `N > L_N^64` を満たす `N` の集合が最初に空でなくなるのは `N = 589^64 + 1`(約 1.94e177)で、この集合は上に閉じていません。`[2^589 - 1, 590^64]` では再び偽になり、それより大きいすべての `N` で成り立つのは `590^64 + 1` からです(`docs/research/thresholds.md` を見てください)。したがって、メモリに載るすべての入力(`N < 2^64`、このとき `L_N^64 >= 2^64 > N`)では、Mode A は基底ケースだけを実行します。

論文は基底ケースを、Lemma 3.2 のスキャン式の Dijkstra 探索、`O(N^2 + m)` と定めています。`N = 10^6` では約 `10^12` 回の演算になり、忠実な基底ケースは、評価計画が求める規模ではベンチマークできません。Lemma 3.2 には、出力(厳密な距離)が同じで、実行時間だけが異なる二分ヒープ式の探索もあります。

## 決定 (Decision)
- `paper-faithful`(Mode A、既定)は、スキャン式の基底ケースを書かれたとおりに実行し、理由 `"outer: N <= L_N^64 (paper base case, scan Dijkstra)"` の `FallbackRecord` を記録します。
- `paper-faithful-d1` は、基底ケースで Lemma 3.2 の二分ヒープ式の探索を実行します。`docs/PAPER_MAPPING.md` に逸脱 **D-1** として挙げ、理由 `"outer: N <= L_N^64 (paper base case, binary-heap Dijkstra, deviation D-1)"` を記録します。
- しきい値の判定は、飽和演算でその場で評価します(`L_N^64` を飽和付きで計算し、`N` と比べます)。条件を満たす集合が上に閉じていないので、事前に計算した境界値とは比べません。
- ベンチマークでは、どちらの変種を計測したかを明記します。どちらの変種も、論文の自明でない構成の計測としては報告しません。その構成が実行されるのは Mode B だけです(`docs/adr/0003-three-implementation-modes.md`)。

## 結果 (Consequences)
- 大規模な「paper-faithful」の時間の計測には `paper-faithful-d1` を使います。これは構造上、Dijkstra 探索に、論文の前処理(長さ 0 の辺の縮約、頂点対ごとの最軽量の辺)を加えたものの時間です。報告では、そうした数値のそばに、その旨を書かなければなりません。
- スキャン版も、小さな `N` で正しさをテストします。これで、忠実なコード経路が検証されます。
