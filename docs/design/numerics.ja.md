# 数値設計: 厳密モデルと IEEE-754 の double

[English](numerics.md) | **日本語** | [简体中文](numerics.zh-CN.md)

論文（arXiv 2611.34911v1、Sec 2）は**比較・加算モデル**で議論する。辺の長さは非負の実数で、アルゴリズムは長さの比較と加算だけを、厳密に行える。CPU の `double` は加算のたびに丸める。この文書は、本プロジェクトが両者をどう区別するか、`double` の結果をどの許容誤差で検査し、それがなぜ妥当か、そして整数の重みをなぜ厳密に検査するかを定める。

コード: `include/sssp/verify.hpp`（`Tolerance`、`verify_sssp`、`write_result_json`）、
`include/sssp/counted.hpp`（`Counted<W>`）、`tests/python/reference/`（厳密な有理数オラクル）。

## 1. 2つの重みの型と、2つの正しさの基準

| 重みの型        | 算術                            | 正しさの基準                                  |
|-----------------|---------------------------------|-----------------------------------------------|
| `std::uint64_t` | 厳密（モデルどおり）            | **厳密**な一致。オーバーフローはエラー        |
| `double`        | IEEE-754 binary64、最近接丸め   | Sec 3 の許容誤差の範囲内、または丸めた代数での厳密一致（Sec 2） |

整数が正しさの主な対象である。整数の入力では、どの和も `WeightTraits<uint64_t>::infinity() = 2^64 - 1` に達しない限り、モデルの演算はすべて厳密になる。したがって論文の実装は厳密な距離を再現しなければならない。`double` の結果は、丸め誤差の上界で判定する。

## 2. 緩和型アルゴリズムが `double` で計算するもの

`fl(x)` を最近接の double への丸めとし、`a ⊕ w = fl(a + w)` と書く。`w ≥ 0` について次が成り立つ。

1. **単調:** `a ≤ b ⇒ a ⊕ w ≤ b ⊕ w`（丸めは単調である）。
2. **非減少:** `a ⊕ w ≥ a`。ただし**狭義ではない**。吸収が起こる: `2^60 ⊕ 1 = 2^60`。

(1)と(2)により、`(double, min, ⊕)` は単調で非減少な経路代数となり、Dijkstra と Bellman–Ford はこの上で正しく動く。したがって両者はまったく同じ値

    d̂(v) = s–v 経路 P すべてにわたる、P の左からの丸め和の最小値

を計算する。この最小値は単純路で達成される（(1)と(2)により、閉路を除いても左畳み込みは増えない）。テストが使う帰結は次のとおり。

* 緩和に基づく任意の2つのアルゴリズム（Bellman–Ford と、すべての Dijkstra の変種）は、`dist` が**ビット単位で**一致しなければならない。異なりうるのは親の木だけである（同点のため）。
* このような結果では、`verify_sssp` の局所検査が**厳密に**成り立つ: すべての弧で `dist[v] == fl(dist[parent] + w)` かつ `dist[v] ≤ fl(dist[u] + w)`。そのため `double` でも既定は `Tolerance::exact()` である。
* 狭義の `<` で緩和すれば、性質(2)により、吸収があっても親のグラフは非巡回に保たれる。

別の結合順序で加算するアルゴリズム（例: あらかじめ求めた近道の長さを使う `d(u) + (w1 + w2)`、Floyd–Warshall の `d[i][k] + d[k][j]`）は、丸めた値が異なるため、緩和の結果と丸めの分だけ異なりうる。許容誤差はそのためにある。

## 3. 許容誤差

`Tolerance{rel, abs}` は、2つの距離の値 `a`、`b` が次を満たすときに受理する。

    |a − b| ≤ rel · max(|a|, |b|) + abs                  （片側: a ≤ b + 同じ余裕）

`Tolerance::for_path_hops(k)` は `rel = γ_k`、`abs = 0` とする。ここで

    u = 2^-53（binary64 の単位丸め）,     γ_k = k·u / (1 − k·u)     （k·u < 1/2 が必要）。

`Tolerance::for_graph(g)` は `k = n − 1` を使う。

### 3.1 なぜ γ_k か

非負の double `x_1..x_m` の和を**任意の**括弧づけ（`m − 1` 回の加算からなる任意の二分木）で取ると、次が成り立つ（Higham, *Accuracy and Stability of Numerical Algorithms*, 第2版, Lemma 3.1 と式 (4.4)）。

    |ŝ − s| ≤ γ_{m−1} · Σ|x_i| = γ_{m−1} · s.

最短路は単純路なので、辺は高々 `n − 1` 本である。`dist[source] = 0` なので最初の加算 `0 + w_1` は厳密であり、丸めが起こる加算は高々 `n − 2` 回である。したがって `γ_{n−1}` は、どの評価順序に対しても安全な（1段階保守的な）上界である。`d*` を厳密な距離、`d̂ = ŝ(P)` を、ある経路 `P`（木の経路）で実現される計算値とする。

* 下側: `d̂ = ŝ(P) ≥ (1 − γ) L(P) ≥ (1 − γ) d*`。
* 上側: `d̂ ≤ ŝ(P*) ≤ (1 + γ) L(P*) = (1 + γ) d*`（アルゴリズムは経路にわたって最小化する）。

よって **`|d̂ − d*| ≤ γ_{n−1} · d*`** となる。これが、`check_double.py` が厳密な有理数 `d*` に対して検査する上界である。

### 3.2 丸めた結果どうしの比較

`a` と `b` がどちらも丸めた結果（例: 論文の実装と double の Floyd–Warshall）なら、それぞれ `γ_k d*` の範囲内にあるので、`|a − b| ≤ 2γ_k d* ≤ 2γ_k/(1 − γ_k) · max(a, b) = γ_{2k} · max(a, b)` となる（恒等式 `2γ_k / (1 − γ_k) = γ_{2k}` は厳密である）。`Tolerance::for_path_hops(2(n − 1))` を使う。`d*` に最も近い double と比べるときは、半 ulp を足す: `γ_k + u ≤ γ_{k+1}`。

### 3.3 既定で絶対項を置かない理由

IEEE-754 の加算は、アンダーフローで精度を失うことがない。2つの double の和が非正規化数なら、その和は厳密である。したがって非負の和では誤差は純粋に相対的で、`abs = 0` となる。`abs` は、比較・加算モデルを承知のうえで外れる呼び出し側（例: 引き算 `d − base` で求めるバケットのキー）や、明示的な余裕がほしい呼び出し側のためにある。使う場所で理由を示さなければならない。

### 3.4 許容誤差のもとで、局所検査が結論できること・できないこと

木の検査 `dist[v] ≈ fl(dist[p] + w)` と証明書 `dist[v] ≲ fl(dist[u] + w)` は、弧ごとに同じ余裕を使う。余裕があると、証明書の議論（`dist[v] ≤ d*(v)`）はホップごとに余裕を1つずつ積み上げるため、許容つきの局所検査だけでは `dist ≤ d*(1 + γ)^{hops}` 型の上界しか証明できない。緩和型でないアルゴリズムの大域的な精度は、参照との比較で確かめる。参照は、厳密な有理数（`check_double.py`）か、`for_path_hops(2(n − 1))` を使った緩和型の結果である。

`check_double.py` は、報告された木の経路の厳密な長さ `L(v)` も抑える。`dist(v)` はその経路の丸め和なので `(1 − rel) L ≤ dist(v) ≤ (1 + rel) d* + abs` が成り立ち、したがって `d* ≤ L ≤ ((1 + rel) d* + abs) / (1 − rel)` となる。

## 4. モデルと double が実際に異なる点

実数では成り立つが double では成り立たない推論であり、`double` のコードで当てにしてはならない。

* **狭義の増加:** `w > 0 ⇒ a + w > a`（吸収があると偽。`tests/support/graphs.hpp` の `extreme_ratio`、重み `2^60` と `1` を参照）。
* **結合法則:** `(a + b) + c = a + (b + c)`（偽。結果が順序に依存する）。
* **桁落ち:** `(a + w) − w = a`（モデルに引き算はなく、`Counted<W>` は引き算を禁じる）。

終了性やバケットの議論に狭義の増加を使うアルゴリズムは、`double` で `extreme_ratio` 型の入力に対してテストしなければならず、主に `uint64_t` で検証する。

## 5. fast-math を禁止する理由

`cmake/Warnings.cmake` は、すべてのターゲットに `-fno-fast-math` を渡す。`-ffast-math` は次を有効にしてしまう。

* `-ffinite-math-only`: コンパイラが無限大は無いと仮定してよくなり、`dist[v] == inf`（本プロジェクトの「到達不能」の番兵）が `false` に畳み込まれうる。黙って誤った結果になる。
* `-fassociative-math` / 再結合: Sec 2 の丸めた経路代数を壊す。緩和型アルゴリズムどうしがビット単位で一致しなくなり、結果が最適化レベルに依存する。
* flush-to-zero / denormals-are-zero: 非正規化数の和が厳密でなくなり、Sec 3.3 が成り立たない。
* `-fno-signed-zeros`、逆数演算: ここでは無害だが、利点もない。

浮動小数点の縮約（FMA）は、距離が加算しか使わないため無関係である。`FLT_EVAL_METHOD == 0`（SSE2 / AArch64、x87 の拡張精度なし）を仮定する。

## 6. 整数の重み: 厳密、かつオーバーフローを検出する

* `infinity() = 2^64 − 1` は予約値であり、有限な距離はすべて `< 2^64 − 1` である。
* `WeightTraits<uint64_t>::checked_add` は、`a + b ≥ infinity()` なら `std::overflow_error` を投げる。
* `bellman_ford` は、オーバーフローする候補を読み飛ばす（最短でない経路上にあるかもしれないため）。収束した後に、有限な頂点に隣接する頂点がまだ無限大のままである場合に限り `std::overflow_error` を投げる。すなわち、真の距離のどれかが表現できないとき、かつそのときに限る。
* `double` でも同じ規則が成り立つ。「無限大に達する」は「丸めた和が `+inf` になる」と読み替える。`WeightTraits<double>::checked_add` は、有限な2つの距離の丸めた和が有限でないとき（例: `1e308 + 1e308`）、到達可能な頂点に対して `+inf`「到達不能」の番兵を返す代わりに `std::overflow_error` を投げる。`bellman_ford` は、Sec 2 の丸めた距離 `d̂(v)` のどれかが `+inf` のとき、かつそのときに限り例外を投げる（詳細: `docs/design/baselines.md`）。
* `verify_sssp` は整数を厳密に比較し、`Tolerance` を無視する。オーバーフローする `dist[parent] + w` は `arithmetic_overflow` として報告する。証明書では、オーバーフローする上界は空虚である（真の制約は範囲の外にある）。

## 7. C++ の `double` の結果を厳密に検証する

1. グラフを辺リスト `n m` / `u v w` として書き出す。重みは `%.17g` で出力する（`Fraction(float(w))` が、C++ のコードが使った double を厳密に復元できるようにするため）。
2. `sssp::write_result_json(os, source, result)` で結果を書き出す:
   `{"n":..,"source":..,"dist":[%.17g or null],"parent":[-1..],"parent_edge":[-1..]}`。
3. `uv run python tests/python/reference/check_double.py graph.txt result.json`
   （`--hops K`、`--rel R`、`--abs A`、`--weights exact` は10進の重みを実数として使う）。
   `fractions.Fraction` で `d*` を再計算し、書き出された各数を、その double の厳密な2進値として読み、Sec 3.1 と木を検査する（終了コード 0 / 1 / 2 = 受理 / 却下 / 読み取り不能）。

書き出しの形式は両側で固定している。`tests/unit/verify/test_verify.cpp` が厳密な文字列を表明し、`tests/python/test_exact_reference.py::test_cpp_dump_format_is_readable_and_exact` が同じ文字列を解析する。

## 8. モデルの演算を数える

`sssp::Counted<W>`（W = `double` または `uint64_t`）は、`+`/`+=` と6つの比較を、スレッドローカルのカウンタ（`counted_stats()`、`reset_counted_stats()`、`CountedScope`）で数える。`-`、`*`、`/` や `W` への逆変換は持たないので、`Counted<W>` でコンパイルできるコードは、重みに対して比較・加算の演算だけを使うことが証明される。`checked_add` のオーバーフロー防御は数えない（モデルの外の帳簿処理である）。制限: `validate_edges` は符号付きまたは浮動小数点の `W` しか検証しないので、負または NaN の `Counted<double>` の重みはグラフの構築時に拒否されない。先に、検証済みの生の重みからグラフを作ること。
